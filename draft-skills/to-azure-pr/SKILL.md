# To Azure PR

Opens a PR in an Azure DevOps Repos repository for the current branch, links it to an Azure Boards work item, waits for the associated pipeline build to complete, and returns structured state. This is the host-specific "done" step for RadiantDev-shaped repos.

## When to invoke

- The repo has `.claude/valk-config.md` with `pr_skill: to-azure-pr`
- The agent is at the end of a TDD slice with passing tests
- The current branch has the commits for the slice and is **not** the target branch (master/main)

If invoked outside these conditions, STOP and report the mismatch. Do not push a half-finished branch.

## Inputs

Pull these from the surrounding context (issue file, git state, valk-config). Don't ask the user for any of them unless inference fails.

| Input | Source | Default if missing |
|---|---|---|
| `branch` | `git rev-parse --abbrev-ref HEAD` | n/a (fail) |
| `target_branch` | `valk-config.azure_devops.target_branch` | `master` |
| `title` | issue title (first H1 in `issues/<n>-*.md`) | first commit subject |
| `description` | issue body + AC checklist + commit list | "Auto-generated by Valkyrie /tdd" |
| `work_item_id` | issue frontmatter `work_item_id:` | none (PR will lack work item link) |
| `org` | `valk-config.azure_devops.org` | `https://dev.azure.com/RadiantDev` |
| `project` | `valk-config.azure_devops.project` | `RadiantAdvanced` |
| `repository` | `valk-config.azure_devops.repository`, or parsed from `git remote get-url origin` | n/a (fail if both absent) |

## Prerequisites

1. **az CLI installed**: `command -v az` returns a path. Install per https://learn.microsoft.com/en-us/cli/azure/install-azure-cli.
2. **azure-devops extension**: `az extension show --name azure-devops` succeeds. Install with `az extension add --name azure-devops`.
3. **Authentication** — one of:
   - **Interactive** (recommended for `/tdd` runs): `az login` once, picks up your Microsoft credentials.
   - **PAT** (required for AFK runs — no human present to approve): export `AZURE_DEVOPS_EXT_PAT` with a PAT scoped to Code (Read & Write) + Build (Read) + Work Items (Read & Write). Generated at https://dev.azure.com/RadiantDev/_usersSettings/tokens.
4. **Working tree clean** (other than the branch's own commits): `git status --porcelain` shows only files this slice touched.

## Flow

1. **Validate prerequisites.** If any of the above fails, STOP with a specific error naming the missing piece.
2. **Push the branch** (with upstream set):
   ```bash
   git push -u origin "$BRANCH"
   ```
3. **Open the PR**:
   ```bash
   az repos pr create \
     --org "$ORG" --project "$PROJECT" --repository "$REPOSITORY" \
     --source-branch "$BRANCH" --target-branch "$TARGET_BRANCH" \
     --title "$TITLE" \
     --description "$DESCRIPTION" \
     ${WORK_ITEM_ID:+--work-items "$WORK_ITEM_ID"} \
     --transition-work-items true \
     --output json
   ```
   Capture `pullRequestId` and `_links.web.href` from the JSON response.
4. **Wait for CI** by polling `az pipelines runs list --branch "$BRANCH"`. Poll every 30 seconds. Time cap: 30 minutes. Exit when the latest run for the branch reaches `status: completed`, or when the cap hits.
5. **Return structured result**:
   ```json
   {
     "pr_id": 4821,
     "pr_url": "https://dev.azure.com/RadiantDev/RadiantAdvanced/_git/<repo>/pullrequest/4821",
     "ci_status": "succeeded",
     "ready_for_review": true
   }
   ```
   `ready_for_review` is `true` only when PR `status == "active"` AND CI `result == "succeeded"`.

## Failure modes and what they mean

| Symptom | Likely cause | Action |
|---|---|---|
| `az: command not found` | az CLI not installed | Stop, tell user to install |
| `Please run 'az login'` | No auth | If interactive: prompt. If AFK: stop with PAT setup instructions. |
| `TF401019: GitRepositoryNotFoundException` | Wrong `repository` value | Stop, surface what was tried |
| `TF401179` | Branch not yet pushed | Re-run `git push` and retry once |
| CI never reaches `completed` within 30 min | Build queue stuck, runner offline, or pipeline misconfigured | Return `ci_status: inProgress`, mark PR not-ready-for-review |
| CI result `failed` | Real test failure or build break | Return `ci_status: failed`, `ready_for_review: false`. Caller decides: mark issue stuck, or comment on the PR and retry |
| `TF401028` (work item not found) | `work_item_id` wrong | Open PR without the link, log a warning |

## How callers use this

**`/tdd` skill** (synchronous): invokes this at end of slice. If `ready_for_review: true` the slice is done. Otherwise leave the issue open with a note describing the failure mode.

**`afk` script** (async): invokes via the helper, reads the JSON, applies the rule: `ready_for_review == true` → mark issue `done` with `pr_url:` written into frontmatter; anything else → mark issue `stuck` with `stuck_reason:` carrying the `ci_status`.
